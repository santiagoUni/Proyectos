# INFORME TÉCNICO - PROYECTO DE SANTIAGO OCAMPO

## ANÁLISIS DE COMPLEJIDAD ALGORÍTMICA

### 1. FORWARD PASS
Complejidad: O(n·h + h·k) = O(12,864) para n=784, h=16, k=10

Desglose:
- z_h = W_ih · x → O(n·h) = O(784·16) = O(12,544)
- a_h = sigmoid(z_h) → O(h) = O(16)
- z_o = W_ho · a_h → O(h·k) = O(16·10) = O(160)
- a_o = sigmoid(z_o) → O(k) = O(10)
Total: O(12,544 + 16 + 160 + 10) = O(12,730)

### 2. BACKPROPAGATION
Complejidad: O(n·h + h·k)

Desglose:
- δ_o = (y - ŷ) ⊙ σ'(z_o) → O(k) = O(10)
- ΔW_ho = δ_o · a_h^T → O(h·k) = O(160)
- δ_h = (W_ho^T · δ_o) ⊙ σ'(z_h) → O(h) = O(16)
- ΔW_ih = δ_h · x^T → O(n·h) = O(12,544)
- Actualización de pesos → O(n·h + h·k)

### 3. MEMORIA
Complejidad espacial: O(n·h + h·k)

Almacenamiento:
- W_ih: 784 × 16 = 12,544 números
- W_ho: 16 × 10 = 160 números
- b_h: 16 números
- b_o: 10 números
- Activaciones: n + h + k = 810 números
Total: ≈ 13,540 números ≈ 54KB (float32)

### 4. ESTRUCTURA HEAP (TOP-K)
Para seleccionar top-k muestras con mayor error:

T(n, k) = O(n log k)

Comparación:
- Heap (top-k): O(n log k) ✓ más eficiente
- Sort + top-k: O(n log n) ✗ menos eficiente
- Para k=100, n=60000: 6M operaciones vs 360M operaciones

### 5. QUICKSELECT (MEDIANA)
Para encontrar umbral mediano de pérdida:

Promedio: T(n) = O(n)
Peor caso: T(n) = O(n²)

Partición:
- Seleccionar pivote aleatorio → O(1)
- Particionar: → O(n)
- Recursión en mitad → T(n/2)
Recurrencia: T(n) = T(n/2) + O(n) → O(n) por Método Maestro

### 6. MÉTODO MAESTRO
Para T(n) = aT(n/b) + f(n):

Si f(n) = Θ(n^d):
- Si a < b^d → T(n) = Θ(n^d)
- Si a = b^d → T(n) = Θ(n^d log n)
- Si a > b^d → T(n) = Θ(n^(log_b a))

Ejemplo QuickSelect: T(n) = 1·T(n/2) + O(n)
- a=1, b=2, d=1
- 1 < 2¹ → T(n) = O(n) ✓

## EXPERIMENTOS Y MEDICIONES

### Escalado con Batch Size (B)
Tiempo por época ∝ número de muestras
- B=1: 60,000 forward+backward → máx tiempo
- B=32: 1,875 mini-lotes → medio
- B=256: 234 mini-lotes → mín tiempo

### Escalado con Hidden Units (h)
Complejidad: O(n·h + h·k)
- h=8: O(6,328) operaciones
- h=16: O(12,730) operaciones (2x)
- h=32: O(25,470) operaciones (4x)

### Escalado con Épocas (E)
Tiempo total: E × (tiempo por época)
Convergencia típica: 50-100 épocas

## DECISIONES DE DISEÑO

1. **Matriz dinámica vs Array plano**
   - Elegido: Matriz 2D para claridad algorítmica
   - Trade-off: Legibilidad > rendimiento micro-optimizado

2. **Sigmoid vs ReLU**
   - Elegido: Sigmoid (derivada más simple)
   - Motivo: Análisis teórico más directo

3. **SGD vs Adam**
   - Elegido: SGD (análisis más simple)
   - Motivo: Enfoque en complejidad algorítmica

4. **Heap vs Array para top-k**
   - Elegido: Heap para demostrar O(n log k)
   - Verificación: Log en las mediciones
